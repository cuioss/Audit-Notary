= Audit Notary Web E2E
:toc: left
:toclevels: 2

The end-to-end suite of the web app: Playwright and axe-core against the Vite dev server of `web-app`, whose `/api`
and `/mock` go to `web-mock` (`doc/specification/testing.adoc`, AUN-TEST-1; the reasoning is ADR-0003). The global
setup starts the mock through `web-mock/start.sh` (profile `workshop`, timing `ordered`) unless one already answers,
and the tests switch profiles through its control routes.

== Running

[source,bash]
----
./mvnw verify -Pe2e -pl web-e2e -am     # through Maven: npm ci, lint, playwright install chromium, playwright test
cd web-e2e && npx playwright test       # directly, after npm ci
npx playwright test tests/login.spec.js # one spec
npx playwright show-report target/playwright-report   # the HTML report of the last direct run
----

Without the profile `e2e` the module only installs and lints; Maven runs the suite with the `list` reporter only.
The suite runs with one worker: every spec changes the state of the one mock server.

Ports: `AUDIT_NOTARY_WEB_PORT` (5173) and `AUDIT_NOTARY_MOCK_PORT` (7420), named only in `tests/helpers/ports.js`
(`scripts/guard-ports.js`).

== Layout

[cols="1,3"]
|===
|Path |Content

|`global-setup.js`
|Starts `web-mock` (or uses the one that answers); the Vite dev server of `playwright.config.js` is already up by then.
It then warms the dev server up: a browser loads `/login` and the shell once and waits until each has drawn itself, so
the first test of a run does not pay for the first transform of every module (see _Cold start_)

|`tests/helpers/mock.js`
|The control routes: `useScenario` (profile, optionally `name#state`), `gotoState`, `broadcast` (an event on the
stream)

|`tests/helpers/login.js`
|The login through the mock, which signs in without a form

|`tests/helpers/a11y.js`
|The axe-core audit; it fails on violations of impact `serious` or `critical`

|`tests/helpers/documents.js`
|The notes of the test category, the paths of their writes at the mock, the choice of the language and the locator of a
field of the generated form

|`tests/helpers/catalogs.js`
|The five catalogs, the addresses and the paths of the writes of the catalogs lens, and the fill of a new service

|`tests/helpers/directory.js`
|The addresses and paths of the directory pages, the static fixtures (persons, result of the import, candidates, the
limits) and the shared steps; the first test of `directory.spec.js` compares the fixtures with the mock

|`tests/helpers/samm.js`
|The addresses and paths of the SAMM completion, the static fixtures (the fixed ids of the creates, the pinned models,
the evidence links and the targets of Payments, the released assessment and its tag), the shared steps and `patchRead`,
which changes the answer of one read where the mock has no state for it; the first test of `samm-completion.spec.js`
compares the fixtures with the mock

|`tests/helpers/reports.js`
|The addresses and paths of the lens Reports, the static fixtures (the figures of the dashboard, the scopes of the trend in

risks now and as of a day or a tag, the refused values), and the shared steps: the rows of a table as text, the colour a
token resolves to, and the check that no text of a chart is smaller than a given size at the width it is drawn; the first
test of `reports.spec.js` compares the fixtures with the mock
|===

|===

A new view gets its address in `navigation.spec.js` and its audit in `theme-readability.spec.js`; a new profile of
`web-mock` gets the spec of the flow it exists for.

The mock stores nothing, and a state it has no profile for is not invented in the page: where a flow needs one (a
trend that leaves versions out, a scope whose targets another assessor saved, a scope that shows no open assessment
while the server knows one, fifty evidence links, a sixth scope in the trend, a third released assessment, a session that
reads no register, a register that answers `FORBIDDEN`), the test fetches the real answer and changes it with `patchRead`, and
says so in a comment.

== Cold start

Vite transforms a module when it is first requested, and the first page of a run asks for about 700 of them. The first
test of a run (`access.spec.js`, a deep link without a session that must reach `/login` within the default timeout of
5 s) used to pay for that: measured on a quiet machine with a fresh dev server, the redirect took 2.0 to 3.5 s on
`main` and on the branch alike (0.35 to 0.45 s once the pages were loaded before), and the whole test 5.6 to 6.3 s
against 1.1 s. On a busy machine the cold redirect passes 5 s and the test fails; it is the same on `main`.
`global-setup.js` therefore loads `/login` and the shell once, in a browser, before the first test and waits for the
pages themselves (`login-view` or `view-title`, up to 120 s), never for a duration. A failed warm-up is a warning; the
tests then say what is wrong.
