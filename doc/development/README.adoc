== Build and Test

The target is Java 25; CI builds on Java 25 and 27. Always build and test through Maven and JUnit.

`./mvnw clean verify` builds every module and runs the unit tests. The end-to-end suite and the integration tests
need the profiles `e2e` and `integration-tests`.

[source,bash]
----
./mvnw clean verify                                           # build and unit tests
./mvnw test -Dtest=ClassName                                  # one test class
./mvnw test -Dtest=ClassName#methodName                       # one test method
./mvnw verify -Pe2e -pl web-e2e -am                           # end-to-end suite
./mvnw verify -Pintegration-tests -pl integration-tests -am   # native image + Keycloak, Docker required
./mvnw package -Pnative -pl audit-notary -am                     # native runner (Mandrel in a container)
docker build -f audit-notary/src/main/docker/Dockerfile.native -t audit-notary:dev audit-notary
./mvnw -Ppre-commit clean verify -DskipTests                  # license headers, OpenRewrite recipes
----

The profile `pre-commit` auto-fixes license headers and every configured OpenRewrite recipe (modernisation, not only
formatting). Review every resulting diff and commit it. The header is the FSL-1.1-ALv2 notice of `src/license/header.txt`;
the root pom's `pre-commit` profile puts it in place of the parent pom's Apache-2.0 header. The plugin covers the Java
sources; a new shell script gets the same text as a `#` comment by hand.

== Working on the Web App

The web app runs in the Vite dev server against the mock server, which answers its requests from a test profile
(link:../../web-mock/README.adoc[web-mock], which lists the profiles):

[source,bash]
----
(cd web-app && npm ci)               # once per checkout; Node >= 22.17 and npm >= 10 (engines of web-app/package.json)
web-mock/start.sh -s workshop        # a profile of the mock, see its README
(cd web-app && npm run dev)          # http://127.0.0.1:5173, /api and /mock go to the mock
web-mock/stop.sh
----

The mock signs in by itself; switch the profile while the app runs with
`curl -X POST http://127.0.0.1:7420/mock/scenario -d '{"scenario":"first-login"}'`.

== Continuous Integration

[cols="1,3"]
|===
|Workflow |What it does

|`maven.yml` (Maven Build)
|Builds and tests on Java 25 and 27, runs Sonar and deploys the SNAPSHOT modules from `main`

|`integration-tests.yml` (Integration Tests)
|Runs `./mvnw verify -Pintegration-tests -pl integration-tests -am`: the native image with Keycloak, on push to `main`,
on pull requests and in the merge queue. It publishes no report pages.

|`release.yml`
|The Maven Central release; see xref:releasing.adoc[Releasing]

|`dependency-review.yml`
|Fails a pull request that adds a dependency with a known vulnerability of high severity or worse

|`scorecards.yml`
|The OpenSSF Scorecard supply-chain check

|`dependabot-auto-merge.yml`
|Marks the pull requests of Dependabot as eligible for auto-merge; the central sweeper of the organisation merges them
|===

`main` is protected. Changes go through a pull request from a branch with a CI-recognised prefix (`feature/`, `fix/`,
`chore/`, `docs/`); the repository's `AGENTS.md` has the workflow.
