= Use Cases: ISMS (UC-ISMS)
:toc: left
:toclevels: 2
:nofooter:

xref:../UseCases.adoc[Use Cases] » ISMS

The ISMS extension keeps the documents an information security management system needs and its risk register, on the
same foundation as the other categories: a lean "ISMS as code" for development organisations, not a replacement for a
complete ISMS product (xref:../concepts/category-isms.adoc[ISMS]). The documents follow the
xref:02-documents.adoc[document use cases].

[#UC-ISMS-1]
== UC-ISMS-1: Maintain and Release ISMS Documents

Status:: `DRAFT`
Actor:: an information security officer with `edit` on `isms-core`; an approver with `approve`, in the web app.
Goal:: keep the policies, the ISMS scope, the internal audit reports and the management reviews as versioned,
approved documents.
Trigger:: a policy is written or revised, an audit or a management review takes place.
Preconditions:: none.
Flow::
+
[source,text]
----
  [U] document.create          one of the document types policy,
       │                       isms-scope,
       │                       audit-report, management-review
       ▼
  ↳ UC-DOC-3, UC-DOC-4         edited and saved
       ▼
  ↳ UC-DOC-6, UC-DOC-7         reviewed and released with step-up
       ▼
  done
----
Outcome:: the current version of each ISMS document is released, and every earlier version stays comparable.
Requirements:: xref:../specification/category-isms.adoc#AUN-ISMS-1[AUN-ISMS-1] (the documents, release with
step-up).
Design:: xref:../concepts/web-app.adoc#_structure_of_the_app[Web App, Structure of the App] (lens *ISMS*). Decided
provisionally for the web app: the four types are documents of `isms-core`, each released more than once, listed by type at
`/isms/documents`, created at `/isms/documents/new?kind=`, and two releases are compared at `/isms/documents/<id>/compare`
(xref:../specification/rest-api.adoc#_decided_isms[REST API Register, Open Questions]).

[#UC-ISMS-2]
== UC-ISMS-2: Maintain the Risk Register

Status:: `DRAFT`
Actor:: an information security officer with `edit` on `isms-register`, in the web app; risks also arrive from SAMM
gaps, threats and incidents.
Goal:: record each risk as an entry with a readable number, treat it, and release its state.
Trigger:: a risk is identified, or comes from xref:04-samm.adoc#UC-SAMM-6[UC-SAMM-6] or
xref:05-threat-models.adoc#UC-TM-3[UC-TM-3].
Preconditions:: none.
Flow::
+
[source,text]
----
  [U] risk.edit                the risk, its owner by role, its
       │                       treatment, measures as issue ids, its
       │                       references
       ▼
  ↳ UC-DOC-4                   the first save assigns the running number
       │                       R-<n>, unique also under concurrent
       │                       creation
       ▼
  ↳ UC-DOC-6                   submitted for review
       ▼
  ↳ UC-DOC-7                   released; the entry reaches main
       ▼
  done
----
Variations::
* *Concurrent creation*: two users creating entries at once get two different numbers.
* *Tasks* stay in the issue tracker; the entry holds their ids only.
Outcome:: the register holds the entry under its number, the target of every reference to it.
Open points:: a measurement of index build time and memory at register size must confirm the design assumption before
the register is built (xref:../concepts/category-isms.adoc[ISMS]); further registers are deferred.
Requirements:: xref:../specification/category-isms.adoc#AUN-ISMS-2[AUN-ISMS-2] (register, running numbers),
xref:../specification/category-isms.adoc#AUN-ISMS-4[AUN-ISMS-4] (operational data by reference); library:
https://github.com/cuioss/git-document-repository/blob/main/doc/specification/git-forms.adoc#GDR-FORMS-9[GDR-FORMS-9].
Design:: xref:../concepts/web-app.adoc#_structure_of_the_app[Web App, Structure of the App] (lens *ISMS*). Decided
provisionally for the web app: the register is at `/isms/risks`, a new risk at `/isms/risks/new`, which stores nothing and shows no
number until the first save assigns it, the owner is a team, and the origin of a risk from a gap or a threat is a read-only
reference (xref:../specification/rest-api.adoc#_decided_isms[REST API Register, Open Questions]).
[#UC-ISMS-3]
== UC-ISMS-3: See the Risk Register as of a Reporting Date

Status:: `DRAFT`
Actor:: an information security officer or an auditor with `read` on `isms-register`, in the web app.
Goal:: show the register exactly as it was released at an audit date or a tag.
Trigger:: an audit, a management review.
Preconditions:: released register entries.
Flow::
. *The date or tag*: the user picks a tag or a date; a date selects the last commit on `main` at or before the end of
  that day (UTC).
. *The register*: the released entries as of then, answered from an index built for that commit, without changing the
  current one.
. *An entry* opens as it was then.
Outcome:: the reader sees the register as of the reporting date, released entries only.
Requirements:: xref:../specification/category-isms.adoc#AUN-ISMS-3[AUN-ISMS-3] (reporting dates).
Design:: xref:../concepts/web-app.adoc#_structure_of_the_app[Web App, Structure of the App] (lens *Reports*); decided
provisionally: the page `/reports/risk-register?as-of=`, which lists summaries of the released entries and opens an entry as it
was then (xref:../specification/rest-api.adoc#_decided_reports[REST API Register, Open Questions]).
