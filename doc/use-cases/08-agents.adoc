= Use Cases: AI Agents (UC-AGT)
:toc: left
:toclevels: 2
:nofooter:

xref:../UseCases.adoc[Use Cases] » AI Agents

A user lets an AI agent work for them: fill in a threat model from a recipe, draft an incident report from notes,
answer questions across the documents. The agent connects to the MCP server with a token of that user and can do no
more than the user may, and the steps that need a human stay with the human
(xref:../concepts/mcp-server.adoc[MCP Server]). What an agent does to a document is in the
xref:02-documents.adoc[document use cases], each of which names its tool.

[#principles]
== Principles

[#bound-to-the-user]
Bound to the user:: Every call carries an audience-bound token of a named user; the effective permission is the
intersection of the token's scopes and the user's rights (xref:../specification/mcp-server.adoc#AUN-MCP-4[AUN-MCP-4]).
[#never-releases]
Never releases:: An agent requests a release; a human completes it with step-up
(xref:../specification/mcp-server.adoc#AUN-MCP-6[AUN-MCP-6]).
[#content-is-data]
Content is data:: What an agent reads may hold text written by anyone with write access; what it writes is validated
and rights-checked like a human's input.

[#UC-AGT-1]
== UC-AGT-1: Connect an Agent

Status:: `DRAFT`
Actor:: a user and the AI agent (MCP client) the user runs.
Goal:: let my agent call Audit Notary in my name, with the scopes I grant, without handing it any other credential.
Trigger:: the user configures the agent with the server's address.
Preconditions:: the user has an account at the organisation's authorization server and has completed the first login
(xref:01-access.adoc#UC-ACC-4[UC-ACC-4]).
Flow::
+
[source,text]
----
  [G] call.unauthenticated     a call without a token
       ▼
  [S] call.401                 401 with the resource metadata address
       │                       and the scope needed
       ▼
  [G] metadata.read            the authorization servers and the scopes
       ▼
  [P] authorize                the user logs in and grants the scopes;
       │                       the token is bound to the server's
       │                       canonical URI
       ▼
  [G] call.authenticated       the call with the bearer token
       ▼
  [S] token.validate           signature, expiry, issuer, audience
       ├── invalid, expired, foreign audience ─► 401
       ├── scope missing ──► 403 insufficient_scope with the scope
       ├── right missing ──► tool error FORBIDDEN
       ├── no directory entry ─► tool error FIRST_LOGIN_REQUIRED
       ▼
  [S] tool.run                 the tool runs as the user; one audit
       ▼                       record per call
  done
----
Variations::
* *A token in the query string* is refused.
* *A foreign `Origin`* is refused with `403`.
* *A local gateway* may hold the user's login for agents that cannot (xref:../concepts/local-mcp-gateway.adoc[Local
  MCP Gateway], a proposal).
* *No credential leaves*: no Git or KMS credential appears in a tool result, an error or a log.
* *Local test users* (login provider `local`, for evaluation and tests only): there is no authorization server and no metadata. The local MCP gateway
  keeps the user's username and password and sends them as HTTP Basic on every call; a wrong or missing credential is
  `401` with a Basic challenge, there are no scopes, and the rights alone decide
  (xref:../specification/mcp-server.adoc#AUN-MCP-8[AUN-MCP-8];
  xref:../concepts/local-mcp-gateway.adoc#_basic_connections[Local MCP Gateway, Basic Connections]).
Outcome:: the agent works for the user with exactly the intersection of scopes and rights, and every call is on
record with pseudonym, client and outcome.
Open points:: the protocol revisions supported besides 2026-07-28; Client ID Metadata Documents or pre-registered
agents (xref:../concepts/mcp-server.adoc#_open_questions[MCP Server, Open Questions]).
Requirements:: xref:../specification/mcp-server.adoc#AUN-MCP-1[AUN-MCP-1] (transport),
xref:../specification/mcp-server.adoc#AUN-MCP-2[AUN-MCP-2] (protected resource metadata),
xref:../specification/mcp-server.adoc#AUN-MCP-3[AUN-MCP-3] (token validation),
xref:../specification/mcp-server.adoc#AUN-MCP-4[AUN-MCP-4] (scopes and rights),
xref:../specification/mcp-server.adoc#AUN-MCP-5[AUN-MCP-5] (no passthrough, no credentials),
xref:../specification/mcp-server.adoc#AUN-MCP-7[AUN-MCP-7] (audit),
xref:../specification/mcp-server.adoc#AUN-MCP-8[AUN-MCP-8] (Basic with local users),
xref:../specification/testing.adoc#AUN-NFR-4[AUN-NFR-4] (token and input tests).
Design:: none; the agent's side is the client's.

[#UC-AGT-2]
== UC-AGT-2: Ask Questions Across the Documents

Status:: `DRAFT`
Actor:: an AI agent for a user.
Goal:: answer the user's questions across categories, such as "which services lack a current threat model" or "what is
due this week", from what the user may read.
Trigger:: the user asks the agent.
Preconditions:: the token carries `audit-notary:read` (<<UC-AGT-1>>).
Flow::
. *Search and lists*: `search` and `list_documents` over the index, only what the user may read.
. *Catalogs*: `read_catalog` for the services, teams and roles.
. *Due items*: `list_due` for deadlines, reviews and pending releases.
. *Documents and diffs*: `read_document` and `diff` for the details.
Variations::
* *A restricted repository*: each document read is logged as for a human (xref:02-documents.adoc#UC-DOC-2[UC-DOC-2]).
Outcome:: the user gets an answer drawn from the documents they may read, and nothing else.
Open points:: the exact tool list per category (xref:../concepts/mcp-server.adoc#_open_questions[MCP Server, Open
Questions]).
Requirements:: xref:../specification/mcp-server.adoc#AUN-MCP-6[AUN-MCP-6] (the read tools),
xref:../specification/architecture-and-modules.adoc#AUN-GEN-2[AUN-GEN-2] (same outcome as the web app).
Design:: none.
