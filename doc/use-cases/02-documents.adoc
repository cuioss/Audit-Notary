= Use Cases: Documents (UC-DOC)
:toc: left
:toclevels: 2
:nofooter:

xref:../UseCases.adoc[Use Cases] » Documents

Every document of every category lives the same life: it is found and read, edited in a form generated from its
schema, kept as a draft until it is saved, saved for everyone with a check for concurrent changes, submitted for
review and released with step-up. The categories (SAMM, threat models, incident reports, ISMS and custom ones) only
add what their schema cannot express. These use cases are built and proven first with the resources-only test
category `test-note` (xref:../specification/architecture-and-modules.adoc#AUN-GEN-1[AUN-GEN-1]).

[#principles]
== Principles

[#one-rule-set]
One rule set for both interfaces:: What a user may do, which validation runs and whether a transition needs step-up is
decided once, in the application services; the web app and the MCP server call the same service with the same input
and get the same outcome (xref:../specification/architecture-and-modules.adoc#AUN-GEN-2[AUN-GEN-2]).
[#saved-for-you-saved-for-everyone]
Saved for you, saved for everyone:: A draft holds the work of one user and stays in the application; a save puts it on
the document's working branch in Git, signed, for everyone
(https://github.com/cuioss/git-document-repository/blob/main/doc/concepts/storage-engine.adoc[Storage Engine]).
[#nothing-lost]
Nothing typed is lost:: A conflict, a validation error or an unreachable Git server never discards a draft.

[#UC-DOC-1]
== UC-DOC-1: Find Documents

Status:: `DRAFT`
Actor:: a user with `read` on a repository, in the web app; an AI agent for the user.
Goal:: find the document I need, by its category and subject or by a search, among the documents I may read.
Trigger:: the user opens a lens, or searches from the top bar.
Preconditions:: the user has a session (or the agent a token with `audit-notary:read`).
Flow::
. *The lens.* The rail offers the lenses Due, SAMM, Threat models, Incidents, ISMS, Catalogs, Reports and Settings; a
  lens shows its chain of levels, for example scope › assessment › practice.
. *The list.* Each level lists the documents with title and state, from the in-memory index, filtered to the
  repositories the user may read.
. *The search.* A query matches the index across the categories and returns only what the user may read.
. *The address.* Selecting a document opens its canonical address; reloading it restores the same view.
Variations::
* *Through an agent*: `list_documents` and `search`.
* *Git server unreachable*: the lists are served from the last fetched state, and the app shows the degraded state
  (xref:10-operations.adoc#UC-OPS-3[UC-OPS-3]).
Outcome:: the user has opened the document, or knows that no readable one matches.
Requirements:: xref:../specification/web-app.adoc#AUN-WEB-3[AUN-WEB-3] (lenses, canonical addresses),
xref:../specification/authentication.adoc#AUN-AUTH-2[AUN-AUTH-2] (only readable repositories),
xref:../specification/mcp-server.adoc#AUN-MCP-6[AUN-MCP-6] (`list_documents`, `search`),
xref:../specification/architecture-and-modules.adoc#AUN-GEN-3[AUN-GEN-3] (the index rebuilt from Git).
Design:: xref:../concepts/web-app.adoc#_structure_of_the_app[Web App, Structure of the App].

[#UC-DOC-2]
== UC-DOC-2: Read a Document

Status:: `DRAFT`
Actor:: a user with `read`, in the web app; an AI agent for the user.
Goal:: read a document as it is now, or as it was at a release or a commit, with its references resolved to names.
Trigger:: the user opens a document (xref:#UC-DOC-1[UC-DOC-1]) or a link to it.
Preconditions:: the user may read the document's repository.
Flow::
. *The document.* The structured fields, laid out by the schema, and the free-text fragments rendered by the server.
. *Its references.* Catalog references show the entry's name, a retired entry as retired; persons show their name
  from the directory, a former member as "former" with role and team.
. *Its state.* Draft, in review or released, with the release tag where there is one, and the user's own unsaved
  draft marked as such.
. *A revision.* The user may choose a release tag or a commit; the document is shown as it was then.
Variations::
* *A restricted repository*: every read is logged with pseudonym, repository and document id for the SIEM.
* *Through an agent*: `read_document`, optionally with a revision; the content it returns is data, never an
  instruction.
* *A reference into a repository the user may not read* is shown as not found.
Outcome:: the user has read the document, and a read in a restricted repository is on record.
Requirements:: xref:../specification/mcp-server.adoc#AUN-MCP-6[AUN-MCP-6] (`read_document`),
xref:../specification/data-protection.adoc#AUN-DP-6[AUN-DP-6] (read-access events),
xref:../specification/data-protection.adoc#AUN-DP-2[AUN-DP-2] (references),
xref:../specification/directory.adoc#AUN-DIR-7[AUN-DIR-7] (former members),
xref:../specification/web-app.adoc#AUN-WEB-8[AUN-WEB-8] (output rendered and sanitised by the server).
Design:: xref:../concepts/web-app.adoc#_security_of_the_page[Web App, Security of the Page].

[#UC-DOC-3]
== UC-DOC-3: Edit a Document with Drafts

Status:: `DRAFT`
Actor:: a team member with `edit`, in the web app; an AI agent for the user.
Goal:: create a document or change one in a form that keeps my work as I type and shows me what others save.
Trigger:: the user creates a document of a document type, or opens one to edit it.
Preconditions:: the user has `edit` on the document type's repository; the document is not frozen (a document type
released once, such as a SAMM assessment, refuses every save after its release).
Flow::
+
[source,text]
----
  [S] form.open                the form generated from the document
       │                       type's schema;
       │                       the blob ids loaded are remembered; an
       │                       existing draft of the user is restored
       ▼
  [U] form.edit                the user changes fields; the browser
       │                       validates against the same schema
       ▼
  [S] draft.write              at most 5 s after the last change, the
       │                       draft is saved for this user only
       ├── field errors ──────► form.edit, the errors per field
       ├── another user saved ─► form.edit, the fields not edited
       │                         locally refreshed in place
       ├── save ──────────────► ↳ UC-DOC-4
       ▼ leave
  done                         the draft stays until it is saved,
                               discarded or expires
----
Variations::
* *Field types*: text, date-time, selection, toggle, tables, catalog pickers, person pickers that store a pseudonym,
  and AsciiDoc fields with a server-rendered preview; free-text fields carry the hint that personal details belong in
  the ticket system.
* *The server's verdict wins*: where the browser's and the server's validation differ, the server's errors are shown.
* *Through an agent*: `write_draft` with the data, validated against the schema; the answer is `DRAFT_SAVED` or the
  field errors.
* *A draft not changed* for the configured period is deleted (`drafts.expiry`).
* *A released document of a document type released more than once* (a threat model, an ISMS document) is reopened by
  its first save after the release: that save starts the next version in the workflow's first state, and its next
  release is tagged `v<n+1>` (<<change-reopen>>).
* *Only what I may read*: the event stream carries the saves of repositories the user may read, and it ends with the
  session (xref:01-access.adoc#UC-ACC-6[UC-ACC-6]).
Outcome:: the user's work is kept as a draft, visible only to them, until it is saved.
Open points:: the AsciiDoc preview runs on the server only, decided provisionally
(xref:../concepts/web-app.adoc#_open_questions[Web App, Open Questions]).
Changes:: xref:01-access.adoc#change-events[Access, the event stream and the session].
Requirements:: xref:../specification/web-app.adoc#AUN-WEB-4[AUN-WEB-4] (generated forms),
xref:../specification/web-app.adoc#AUN-WEB-5[AUN-WEB-5] (drafts, event stream),
xref:../specification/data-protection.adoc#AUN-DP-5[AUN-DP-5] (pseudonyms, free-text hint),
xref:../specification/mcp-server.adoc#AUN-MCP-6[AUN-MCP-6] (`write_draft`),
xref:../specification/configuration.adoc#AUN-CONF-1[AUN-CONF-1] (`drafts.expiry`); library:
https://github.com/cuioss/git-document-repository/blob/main/doc/specification/git-forms.adoc#GDR-FORMS-2[GDR-FORMS-2].
Design:: xref:../concepts/web-app.adoc#_forms_from_schemas[Web App, Forms from Schemas],
xref:../concepts/web-app.adoc#_drafts_saving_and_conflicts[Drafts, Saving and Conflicts].

[#UC-DOC-4]
== UC-DOC-4: Save a Document and Resolve a Conflict

Status:: `DRAFT`
Actor:: a team member with `edit`, in the web app; an AI agent for the user.
Goal:: make my draft the document everyone sees, without overwriting what someone else saved meanwhile.
Trigger:: the user saves the draft (xref:#UC-DOC-3[UC-DOC-3]).
Preconditions:: the user has a draft of the document and `edit` on its repository.
Flow::
+
[source,text]
----
  [S] save.validate            first whether the document is frozen;
       │                       then the schema, required excepted, and
       │                       every reference resolved
       ├── frozen document ───► done, DOCUMENT_RELEASED; the draft stays
       ├── field errors ──────► done, the errors per field, among them
       │                        REFERENCE_NOT_FOUND; the draft stays
       ▼
  [S] save.apply               the draft applied onto the tip of the
       │                       working branch as one signed commit, by
       │                       the blob ids loaded; the frozen state
       │                       checked again in the same atomic step
       ├── released meanwhile ──────► done, DOCUMENT_RELEASED; the draft
       │                              stays
       ├── a file changed meanwhile ─► save.conflict
       ├── push refused ────────────► done, REJECTED; the draft stays
       ├── Git server unreachable ──► done, GIT_UNAVAILABLE; the draft
       │                              stays, the user saves again later
       ▼
  [S] save.done                SAVED; the index refreshed; other editors
       ▼                       see it within 5 s
  done
  [U] save.conflict            per file the fields that differ, own and
       │                       other value side by side; the user
       │                       decides per field
       ▼
  save.validate                with the decided values and the new
                               blob ids
----
Variations::
* *Different parts*: where the schema splits a document into files (a SAMM practice, for example), saves to different
  files never conflict.
* *Generated output* takes no part in the conflict check; each save regenerates it in the same commit.
* *Step-up*: a save needs none under the delivered workflows; where a workflow asks for it, the save returns
  `STEP_UP_REQUIRED` (xref:01-access.adoc#UC-ACC-3[UC-ACC-3]).
* *A release in between*: a release that completes after `save.validate` cannot let the save through; `save.apply`
  checks the frozen state again atomically with the write, and a save that loses the race answers `DOCUMENT_RELEASED`
  with the draft unchanged (<<change-frozen-at-write>>).
* *Released, not frozen*: the first save after a release of a document type released more than once is applied
  like any other; it starts the next version in the workflow's first state (<<change-reopen>>). Only a frozen
  document (a released SAMM assessment) answers `DOCUMENT_RELEASED`.
* *Through an agent*: `save` with the blob ids it loaded; the same outcomes, a conflict per file with both values.
Outcome:: the document holds the user's changes on its working branch, signed in the user's name; nothing anyone saved
meanwhile was lost.
Requirements:: xref:../specification/architecture-and-modules.adoc#operation-outcomes[Operation Outcomes] (the
outcomes of a save), xref:../specification/web-app.adoc#AUN-WEB-5[AUN-WEB-5] (save and conflict),
xref:../specification/data-protection.adoc#AUN-DP-2[AUN-DP-2] (reference check),
xref:../specification/architecture-and-modules.adoc#AUN-GEN-6[AUN-GEN-6] (unreachable Git server),
xref:../specification/authentication.adoc#AUN-AUTH-3[AUN-AUTH-3] (signed commit, trailers),
xref:../specification/authentication.adoc#AUN-AUTH-5[AUN-AUTH-5] (technical user, `REJECTED`),
xref:../specification/testing.adoc#AUN-NFR-2[AUN-NFR-2] (save latency); library:
https://github.com/cuioss/git-document-repository/blob/main/doc/specification/git-store.adoc[`git-store`].
Changes:: <<change-reopen>>, <<change-frozen-at-write>>.
Design:: xref:../concepts/web-app.adoc#_drafts_saving_and_conflicts[Web App, Drafts, Saving and Conflicts].

[#UC-DOC-5]
== UC-DOC-5: Discard a Draft

Status:: `DRAFT`
Actor:: an AI agent for a user.
Goal:: throw away a draft the agent wrote for the user, so the user starts again from the saved document.
Trigger:: the agent or the user decides the draft is wrong.
Preconditions:: the token carries `audit-notary:write`; the user has a draft of the document.
Flow::
+
[source,text]
----
  [G] draft.discard            discard_draft for the document
       ▼
  [S] draft.delete             the user's draft is deleted; the saved
       ▼                       document is unchanged
  done                         DISCARDED
----
Variations::
* *In the web app*: not offered; a draft there ends by saving or by expiry.
Outcome:: the user has no draft of the document; the document is as last saved.
Open points:: whether the web app should offer discarding a draft too.
Requirements:: xref:../specification/architecture-and-modules.adoc#AUN-GEN-2[AUN-GEN-2] (tools without a web-app
equivalent), xref:../specification/mcp-server.adoc#AUN-MCP-6[AUN-MCP-6] (`discard_draft`).

[#UC-DOC-6]
== UC-DOC-6: Submit a Document for Review

Status:: `DRAFT`
Actor:: a team member with `edit`, in the web app.
Goal:: say that the document is complete and ready for the approver.
Trigger:: the user submits the document.
Preconditions:: the document is saved and in the workflow's first state.
Flow::
+
[source,text]
----
  [S] submit.check             the schema including required
       ├── fields missing ─► done, MANDATORY_FIELDS_MISSING with the
       │                     JSON Pointers of the missing fields
       ▼
  [S] submit.write             the transition written and saved
       ▼                       (in-review); the approvers see it due
  done
----
Variations::
* *Saving goes on*: the document can still be saved while in review, where the category's workflow allows it.
* *Step-up*: none under the delivered workflows; where a workflow asks for it, ↳ UC-ACC-3.
* *Through an agent*: there is no tool for this transition; the agent requests a release instead
  (xref:#UC-DOC-8[UC-DOC-8]).
Outcome:: the document is in review and appears in the approvers' *Due* lens.
Requirements:: xref:../specification/architecture-and-modules.adoc#operation-outcomes[Operation Outcomes]
(transition into review), xref:../specification/category-incident-reports.adoc#AUN-IR-3[AUN-IR-3] (mandatory fields,
the pattern every category follows); library:
https://github.com/cuioss/git-document-repository/blob/main/doc/specification/git-forms.adoc#GDR-FORMS-2[GDR-FORMS-2].
Design:: none yet.

[#UC-DOC-7]
== UC-DOC-7: Review and Release a Document

Status:: `DRAFT`
Actor:: an approver with `approve`, in the web app.
Goal:: see exactly what changed since the last release and freeze the document as evidence, in my name.
Trigger:: the document waits in the approver's *Due* lens, or the approver opens its release.
Preconditions:: the document is in review; the approver has `approve` on its repository.
Flow::
+
[source,text]
----
  [S] release.diff             the structured diff against the last
       │                       released state, grouped by schema section
       ▼
  [U] release.decide           release, or back to editing
       ├── back ─────────► done; where the workflow declares a
       │                   transition back to its first state, it
       │                   is written like any other transition:
       │                   with edit, and with step-up (UC-ACC-3)
       │                   where the workflow requires it;
       │                   otherwise nothing is written and the
       │                   document is edited in review
       ▼ release
  [S] release.check            required fields
       ├── fields missing ─► done, MANDATORY_FIELDS_MISSING
       ▼
  ↳ UC-ACC-3                   step-up, when the workflow requires it
       ├── not confirmed ─► done, nothing written
       ▼
  [S] release.write            exactly the revision whose diff was
       │                       shown, merged into main by the
       │                       application, tagged <collection>/<id>/v<n>,
       │                       signed with the approver in the trailers
       ├── saved since the diff ─► release.diff, CHANGED_SINCE_REVIEW;
       │                           the approver reviews the new diff
       ├── push refused ──────► done, REJECTED
       ├── Git unreachable ───► done, GIT_UNAVAILABLE
       ▼
  done                         RELEASED
----
Variations::
* *Through an agent*: an agent cannot release; it requests the release (xref:#UC-DOC-8[UC-DOC-8]).
* *A category that is released once*, such as a SAMM assessment, refuses every later save
  (xref:04-samm.adoc#UC-SAMM-4[UC-SAMM-4]).
* *Editing in review*: the delivered workflows allow saves in review, so "back to editing" writes nothing; a workflow
  that does not allow them declares a transition back to its first state.
* *Back without `edit`*: the transition back is no release, so it needs `edit`
  (xref:../specification/authentication.adoc#AUN-AUTH-2[AUN-AUTH-2]) and the step-up its workflow asks for; an approver
  who has only `approve` leaves the document in review, and a user with `edit` takes it back.
* *Saved after the diff*: a release never includes content the approver did not see; a save after the diff makes the
  release show the new diff instead (<<change-reviewed-revision>>).
* *Anchoring*: the release is anchored when an anchor provider is active (`anchor.provider` other than `none`).
Outcome:: the released state is on `main` under a protected tag, signed in the approver's name, and immutable.
Requirements:: xref:../specification/web-app.adoc#AUN-WEB-6[AUN-WEB-6] (diff and release),
xref:../specification/authentication.adoc#AUN-AUTH-4[AUN-AUTH-4] (step-up),
xref:../specification/authentication.adoc#AUN-AUTH-5[AUN-AUTH-5] (the application merges and pushes),
xref:../specification/architecture-and-modules.adoc#operation-outcomes[Operation Outcomes] (the outcomes of a
release), xref:../specification/configuration.adoc#AUN-CONF-1[AUN-CONF-1] (`anchor`); library:
https://github.com/cuioss/git-document-repository/blob/main/doc/specification/git-store.adoc[`git-store`].
Changes:: <<change-reviewed-revision>>, <<change-back-to-editing>>.
Design:: xref:../concepts/web-app.adoc#_review_and_release[Web App, Review and Release].

[#UC-DOC-8]
== UC-DOC-8: An Agent Requests a Release, a Person Completes It

Status:: `DRAFT`
Actor:: an AI agent for a user, then that user, or an approver, in the web app.
Goal:: let the agent hand a finished document to a human for release, without ever releasing itself.
Trigger:: the agent has finished a document for the user, for example a threat model from a recipe.
Preconditions:: the token carries `audit-notary:request-release`; the document is saved, in its workflow's first state
or in review.
Flow::
+
[source,text]
----
  [G] request.create           request_release with a comment
       ▼
  [S] request.save             the request saved in Git
       ├── push refused ───► done, REJECTED
       ├── Git unreachable ─► done, GIT_UNAVAILABLE
       ▼
  [S] request.pending          RELEASE_REQUESTED with the request id;
       │                       shown in the Due lens of the requesting
       │                       user
       ▼
  [U] request.open             the user opens the request
       ├── document in its first state ─► ↳ UC-DOC-6, submitted for
       │                                  review by a user with edit
       ▼ document in review
  ↳ UC-DOC-7                   review and release, with step-up, by a
       ▼                       user with approve
  done
----
Variations::
* *Not approved*: the request stays pending; the document can be edited further.
* *No submit by the agent*: an agent has no tool for the transition into review, so a human submits the document when
  the request is opened (xref:#UC-DOC-6[UC-DOC-6]).
Outcome:: the release, if it happens, is a human act with step-up; the request and its comment are on record.
Open points:: how a release request is stored in Git: as a field of the document on its working branch, or as a
document of a document type of its own, and in which repository
(xref:../concepts/mcp-server.adoc#_open_questions[MCP Server, Open Questions]); whether a pending request is also shown
to the approvers, not only to the requesting user.
Requirements:: xref:../specification/mcp-server.adoc#AUN-MCP-6[AUN-MCP-6] (human-bound releases),
xref:../specification/architecture-and-modules.adoc#AUN-GEN-3[AUN-GEN-3] (open requests are documents),
xref:../specification/architecture-and-modules.adoc#operation-outcomes[Operation Outcomes] (request a release).
Design:: xref:../concepts/web-app.adoc#_structure_of_the_app[Web App, Structure of the App] (lens *Due*).

[#UC-DOC-9]
== UC-DOC-9: Work Through What Is Due

Status:: `DRAFT`
Actor:: any user, in the web app; an AI agent for the user.
Goal:: see in one place what waits for me: deadlines, reviews and releases, the most urgent first.
Trigger:: the user opens the application; the *Due* lens is the start page.
Preconditions:: the user has a session.
Flow::
. *Deadlines*: due times computed from the documents' workflows, such as the notification deadlines of an incident
  (xref:06-incidents.adoc#UC-IR-2[UC-IR-2]) or a threat model's review (xref:05-threat-models.adoc#UC-TM-2[UC-TM-2]).
. *Reviews*: documents in review the user may approve.
. *Releases*: pending release requests (xref:#UC-DOC-8[UC-DOC-8]).
. *Repositories*: for a catalog administrator, repositories whose retention period has ended
  (xref:10-operations.adoc#UC-OPS-4[UC-OPS-4]).
. *Each item* names its kind (deadline, review or release), lens, title and due date and opens its canonical address.
Variations::
* *Through an agent*: `list_due`.
* *Reminders* are recomputed from the index every minute; they are run-time state, not persistence.
Outcome:: the user knows what is due and has opened the item to work on.
Requirements:: xref:../specification/web-app.adoc#AUN-WEB-9[AUN-WEB-9] (`GET /api/v1/due`),
xref:../specification/mcp-server.adoc#AUN-MCP-6[AUN-MCP-6] (`list_due`),
xref:../specification/architecture-and-modules.adoc#AUN-GEN-3[AUN-GEN-3] (reminders from the index); library:
https://github.com/cuioss/git-document-repository/blob/main/doc/specification/git-forms.adoc#GDR-FORMS-6[GDR-FORMS-6]
(deadline rules).
Design:: xref:../concepts/web-app.adoc#_structure_of_the_app[Web App, Structure of the App] (lens *Due*,
`DashboardPage`).

[#changes-to-the-specification]
== Changes to the Specification

Each change is the fix of a gap these use cases need; it is written into the specification once they are `AGREED`.

[[change-reviewed-revision]]Operation Outcomes, the reviewed revision:: Gap: the release does not say which revision
it merges, so a save after the diff could be released unseen. Fix: the release request carries the commit the diff was
made from; the release merges exactly that commit, and answers `CHANGED_SINCE_REVIEW` when the working branch has
moved since (xref:../specification/architecture-and-modules.adoc#operation-outcomes[Operation Outcomes], release row;
xref:../specification/web-app.adoc#AUN-WEB-6[AUN-WEB-6]).
[[change-back-to-editing]]Workflows, back to editing:: Gap: no transition leads from review back to the first state.
Fix: a workflow that does not allow saves in review declares the transition back to its first state; the delivered
workflows allow saves in review and need none
(xref:../specification/category-samm.adoc#AUN-SAMM-3[AUN-SAMM-3] states it for SAMM).
[[change-reopen]]Workflows, the next version:: Gap: the specification does not say how a document released more than
once returns from `released` to editing. Fix: for such a document type the first save after a release starts the
next version in the workflow's first state; the next release is tagged `v<n+1>`; a document type released once (SAMM
assessment) refuses the save with `DOCUMENT_RELEASED`.
[[change-frozen-at-write]]Operation Outcomes, the frozen check at the write:: Gap: the specification refuses saves to a
released assessment (xref:../specification/category-samm.adoc#AUN-SAMM-4[AUN-SAMM-4]) but does not say when the
check is made, so a release that completes between the check and the write would let the save through; the blob-id
check does not catch it when the release changes none of the loaded files. Fix: the save checks the frozen state in
the same atomic step as the write, and a save that loses the race answers `DOCUMENT_RELEASED` with the draft unchanged
(xref:../specification/architecture-and-modules.adoc#operation-outcomes[Operation Outcomes], save row).
