= Audit Notary -- Documentation Index
:toc: left
:toclevels: 3
:toc-title: Table of Contents
:sectnums:
:source-highlighter: highlight.js

*Audit Notary* is the server application in which a development organisation maintains its
OWASP SAMM assessments, threat models, incident response reports and ISMS documents as versioned documents, on the Git
server it already runs. It is built on the libraries of `git-document-repository` and the Token Sheriff libraries, runs as a Quarkus
native application on Java 25, and has two user interfaces: a web app for people and an MCP server for AI agents
acting for a user.

[NOTE]
====
This directory documents the application, not the libraries. It was written in the
https://github.com/cuioss/git-document-repository[`git-document-repository`] repository (as `doc/app/`) and moved here
in one go on 2026-11-20. It is self-contained: its diagrams are in `resources/diagrams/`, its decisions in `adr/`, and it
links into the library documentation, by absolute address, only to the library concepts and specifications.
====

New readers start with the xref:concepts/audit-notary-overview.adoc[Overview]; operators with
xref:concepts/deployment.adoc[Deployment] and xref:specification/configuration.adoc[Configuration]; whoever implements
the next feature with the xref:UseCases.adoc[Use Cases] and their order.

[#_use_cases]
== Use Cases

xref:UseCases.adoc[Use Cases] describe what a person does with the application and what they get out of it, one module
per area (`use-cases/NN-<area>.adoc`, identifiers `UC-<AREA>-<n>`). They name the requirements that serve them, list
the changes of the specification they still need, and give the order in which they are implemented. Every use case is
`DRAFT` until the owner agrees to it.

[#_specification]
== Specification

Each specification document states its requirements as numbered sections (`AUN-<GROUP>-<n>`): first the rules that
must hold, then the design that realises them. The application is in its bootstrap: the concepts and specifications
describe its full design, including every check and CI job they name, and the modules built so far are listed in
xref:specification/architecture-and-modules.adoc#_maven_modules[Architecture and Modules]. Each module documents its
layout and commands in its own `README.adoc`.
