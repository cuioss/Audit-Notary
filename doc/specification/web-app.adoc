[#AUN-WEB-2]
== AUN-WEB-2: Visual Language and Accessibility

* The app must use the design-token contract of `pm-web-app` — its token names — with Audit Notary's own values in a
  light and a dark theme (xref:../concepts/visual-design.adoc[Visual Design]); no raw colour literal may appear in a
  view or a component (stylelint).
* Every field boundary must reach 3:1 against the sheet (WCAG 2.1 success criterion 1.4.11), and the accessible name
  of a control must contain its visible label (success criterion 2.5.3).
* Text contrast must meet WCAG 2.1 AA in both themes, verified automatically; the axe-core audit must report no
  violation of impact `serious` or `critical`.

Tokens, fonts and checks:

* `src/styles/tokens.css`: the token contract of `pm-web-app`; `:root` light, dark under `prefers-color-scheme` and
  `[data-theme]`. `src/lib/theme.ts`: light, dark, system; stored in `localStorage` key `audit_notary_theme`.
* Inter (the interface) and Source Serif 4 (the record: sheet titles, section heads, question texts, figures) as
  variable fonts self-hosted in `static/fonts/` with their licence files, both under the SIL Open Font License 1.1;
  own icon set in `src/lib/icons/`.
* Contrast: an automated test computes the relative luminance of WCAG 2.1
  (link:https://www.w3.org/TR/WCAG21/#dfn-relative-luminance[definition]) for every text/background token pair in both
  themes; below 4.5:1 (3:1 for large text) fails, the thresholds of success criterion 1.4.3, level AA
  (link:https://www.w3.org/TR/WCAG21/#contrast-minimum[WCAG 2.1, 1.4.3 Contrast (Minimum)]). axe-core runs in
  `web-e2e` on every view.

[#AUN-WEB-3]
== AUN-WEB-3: Navigation

* The app must offer the lenses Due, SAMM, Threat models, Incidents, ISMS, Catalogs, Reports and Settings.
* Every object kind must have exactly one canonical address; reloading an address must restore the same view.

Canonical addresses: `/` (Due), `/samm/<scope>/<assessment>/<practice>`, `/threat-models/<service>/<model>`,
`/incidents/<year>/<incident>`, `/isms/risks/<entry>`, `/isms/documents/<id>`, `/catalogs/<catalog>/<id>`,
`/reports/<report>`, `/settings/<section>`, `/welcome` (first login) and `/<lens path>/release`. `src/lib/routes.ts`
holds `parseAddress` and `formatAddress`; route files are stubs rendering `AppRouter`.

Provisionally (decided with the document lifecycle, xref:rest-api.adoc#_the_generic_documents_lens[REST API Register,
The Generic Documents Lens]): a ninth lens, *Documents*, shows the categories without a lens of their own at
`/categories`, `/categories/<category>`, `/categories/<category>/new`, `/categories/<category>/<document>` and
`/categories/<category>/<document>/release`; and an address may admit a few named query parameters that belong to its
canonical form (xref:rest-api.adoc#_allowed_queries[REST API Register, Allowed Queries of an Address]): `at` on a
document address reads the document as it was at a release or a commit. `parseAddress` and `checkReturn` read them
under the rules of that section; every other query parameter is ignored in an address and refused in a login's
`return`.

Provisionally (decided with the directory and the catalogs, xref:rest-api.adoc#_directory_addresses[REST API Register,
Directory and Catalog Requests]): the lens *Catalogs* gains `/catalogs/<catalog>/new` and the administration pages
`/directory/import` (the Backstage import) and `/directory/persons` (prefilled persons and erasure), and the own
directory entry is `/settings/profile`. The administration pages belong to the lens *Catalogs* although their path starts
with `/directory`, which never meets `/catalogs/<catalog>`.

Provisionally (decided with the SAMM completion, xref:rest-api.adoc#_samm_addresses[REST API Register, SAMM Requests]): the
lens *SAMM* gains `/samm/new` (a new scope) and `/samm/<scope>/new` (a new assessment); the segment `new` is reserved as a
scope and as an assessment.

Provisionally (decided with the Reports lens, xref:rest-api.adoc#_reports_addresses[REST API Register, Reports Requests]): the
lens *Reports* gains `/reports/samm-trend`, `/reports/samm-compare`, `/reports/threat-evaluation` and
`/reports/risk-register`, with the allowed queries `scope`, `from`, `to` and `as-of`; `/reports/<report>` stays for every
other name and is the not-found view. The address of a risk (`/isms/risks/<entry>`) admits `at`.

Provisionally (decided with the threat models, xref:rest-api.adoc#_threat_model_addresses[REST API Register, Threat Model
Requests]): the lens *Threat models* gains `/threat-models/<service>/new` (the recipe wizard, with the allowed query `recipe`);
the segment `new` is reserved as a model, and the address of a model admits `at`.

Provisionally (decided with the incident reports, xref:rest-api.adoc#_incident_addresses[REST API Register, Incident Report
Requests]): the lens *Incidents* gains `/incidents/<year>/new` (a new incident); the segment `new` is reserved as an incident,
the id of an incident is a ULID (case sensitive), and the address of an incident admits `at` and `stage` (the tab).

Three more addresses are shown without the shell: `/login` (local users), `/signed-out` and `/login-problem`
(provisional, xref:rest-api.adoc#_addresses_outside_the_shell[REST API Register, Addresses Outside the Shell]). They are
in `canonical-addresses.json` as `outsideShell`, so the web app routes them and the check of a login's `return` refuses
them: a login does not return to the page that started it.

[#_the_schema_the_form_reads]
=== The Schema the Form Reads

The form reads the schema of a document's kind with `GET /api/v1/categories/{category}/schema`
(xref:rest-api.adoc#_form_kit_requests[REST API Register, Form Kit Requests]; PROVISIONAL). The schema is the kind's
`<kind>/schema.json` as the library reads it: plain JSON Schema of the dialect Draft 2020-12, every marker an `x-`
keyword or the library's `format: gdr-link` (xref:data-protection.adoc#AUN-DP-2[AUN-DP-2],
xref:architecture-and-modules.adoc#AUN-GEN-1[AUN-GEN-1],
https://github.com/cuioss/git-document-repository/blob/main/doc/specification/git-forms.adoc#GDR-FORMS-2[GDR-FORMS-2]).
The form resolves a `$ref` that selects a schema of the same file, as the library does, and nothing else; it ignores
`title`, `description` and `default`, because every text of the form comes from the message catalogue
(<<AUN-WEB-7>>). The properties of an object are shown in the order of the schema file.

[#_choosing_the_component]
=== Choosing the Component

The component of a property is the first rule that matches, after `$ref` has been resolved. A marker on a schema of
another type than the one named (`x-catalog` on a number) is ignored.

[cols="1,3,2"]
|===
|# |Rule |Component

|1 |`readOnly: true` |The value as the kind of the following rules would show it, not editable
|2 |`type: string` with `x-catalog: <catalog>` |`CatalogPicker`
|3 |`type: string` with `x-person: true` |`PersonPicker`
|4 |`type: string` with `x-asciidoc: true` |`AsciiDocField`
|5 |`type: string` with `format: gdr-link` |`DocumentRefField`
|6 |`type: string` with `format: date-time` or `format: date` |`DateTimeField`
|7 |`enum` whose members are all strings, numbers or booleans |`Select`
|8 |`type: boolean` |`Toggle`
|9 |`type: string` |`Field` (text; a text area with `x-free-text: true`)
|10 |`type: integer` or `type: number` |`Field` (number)
|11 |`type: object` with `properties` |A section: a heading and the fields of its properties
|12 |`type: array` whose `items` follow rules 2 to 11
|`DataTable`: one column for a scalar item, the scalar properties of an object item
|13 |Anything else, an array inside a row of a `DataTable` included |The value as plain data, read-only
|===

`x-free-text: true` adds the hint to the property whatever its component, to an `AsciiDocField` too. A `DataTable`
shows the first four scalar properties of a row as columns; the row editor, a dialog, edits every property of one
row with the components above. A row can be added, edited, removed and moved up or down; `minItems`, `maxItems` and
`uniqueItems` limit what the table lets the user do and are checked like any other constraint. A property that rule 13
leaves as plain data is never changed by the form: a save sends it as the document holds it.

[#_values]
=== Values

The form edits one JSON value, the data of the part it shows (for a document with one file the document's data), and
names a field by the JSON Pointer of its place in that value
(link:https://www.rfc-editor.org/rfc/rfc6901[RFC 6901]); the item of a `DataTable` is addressed by its index
(`/items/0/title`). What the components store:

[cols="1,3"]
|===
|Component |Value

|`Field` (text)
|A string; an empty text field removes the property from the value

|`Select`
|The member of the `enum` as the schema holds it, with its JSON type: a string, a number or a boolean (`true` stays the
boolean, not the text `"true"`)

|`Field` (number)
|A number; an empty field removes the property

|`Toggle`
|A boolean

|`DateTimeField`
|With `date-time`, an RFC 3339 instant in UTC to the second (`2026-11-24T09:30:00Z`), shown and entered in the time
zone of the browser; a value the user did not touch is stored back unchanged, whatever its offset. With `date`, a
calendar date `YYYY-MM-DD`

|`CatalogPicker`
|The reference `<catalog>:<id>` (`service:payment-api`), the form of
https://github.com/cuioss/git-document-repository/blob/main/doc/specification/git-forms.adoc#GDR-FORMS-8[GDR-FORMS-8]

|`PersonPicker`
|The pseudonym (`p-…`), never a name (xref:data-protection.adoc#AUN-DP-5[AUN-DP-5])

|`AsciiDocField`
|The AsciiDoc source as a string; the rendered HTML is never stored

|`DocumentRefField`
|The reference `<alias>:<kind>/<id>` with an optional `#<fragment>`

|`DataTable`
|An array
|===

[#_labels_and_texts]
=== Labels and Texts

No text comes from the schema. The category's messages (xref:../use-cases/09-categories.adoc#change-web-7[UC-KND,
texts of custom categories]) merge into the catalogue under `category.<category>.` (<<AUN-WEB-7>>); a property
`/a/b` of the kind `<kind>` uses these keys, with the indices of arrays left out (PROVISIONAL):

[cols="2,3"]
|===
|Key |Text

|`category.<category>.<kind>.field.a.b`
|The label of the field, or the heading of a section

|`category.<category>.<kind>.field.a.b.help`
|A line of help under the field; optional

|`category.<category>.<kind>.field.a.b.option.<value>`
|The text of an `enum` value; without the key the form shows the value
|===

A property without a label key shows its property name, so that a missing text is visible. The fixed texts of the
form belong to the application: `form.hint.no-personal-notes` (specified), and by the same pattern the texts of the
pickers, the table, the preview and the errors (`form.error.<code>`, below).

[#_validation]
=== Validation

The browser checks the value against the schema without a validator library (PROVISIONAL: the earlier text named
Ajv; no dependency is added for it, and the checks below are the ones the components need). It checks `type`, `enum`,
`const`, `minLength`, `maxLength`, `pattern`, `minimum`, `maximum`, `exclusiveMinimum`, `exclusiveMaximum`,
`minItems`, `maxItems`, `uniqueItems` and `format`, and lists the mandatory fields from `required`. It does not check
what it never offers: `additionalProperties`, `patternProperties`, `oneOf`, `anyOf`, `not`, `if`, `dependentRequired`
and the other keywords, which only the server checks. A `pattern` is matched anywhere in the value, as the library's
validator does (`Matcher.find`); a pattern the browser cannot compile is not checked.

* *`required`* marks the label of the field. A missing mandatory field is no error on a draft or a save, because the
  library accepts a save without them (GDR-FORMS-2); it is listed, as the JSON Pointers of the empty fields, for the
  transition that needs them, and the server names them in `MANDATORY_FIELDS_MISSING`.
* *`format`* is an annotation for the library: its validator asserts no format (GDR-FORMS-2). The browser asserts
  `date-time`, `date` and the shape of `gdr-link` (`<alias>:<kind>/<id>[#<fragment>]` or `<catalog>:<id>`, the parts
  not empty, no white space), so a format error of the browser can stand where the server finds none. It is shown as
  an error of the field and never stops a draft or a save.
* *The server's verdict wins.* A refusal `422 VALIDATION` carries `errors`, a list of `{"pointer", "code"}`
  (<<AUN-WEB-9>>). The form shows them at their fields and takes them in place of every error of its own, so a
  browser error that the server did not repeat disappears when the answer arrives; the error of a field goes when the
  field changes, and the browser checks it again then. An error whose pointer names no field of the form is listed
  under the form.
* *The codes* the form has a text for (PROVISIONAL): `REFERENCE_NOT_FOUND` (specified,
  xref:data-protection.adoc#AUN-DP-2[AUN-DP-2]), `PSEUDONYM_UNKNOWN` (xref:data-protection.adoc#AUN-DP-5[AUN-DP-5]),
  and the keyword of the failing constraint in capitals (`TYPE`, `ENUM`, `CONST`, `MIN_LENGTH`, `MAX_LENGTH`,
  `PATTERN`, `MINIMUM`, `MAXIMUM`, `EXCLUSIVE_MINIMUM`, `EXCLUSIVE_MAXIMUM`, `MIN_ITEMS`, `MAX_ITEMS`,
  `UNIQUE_ITEMS`, `FORMAT`). The text is the catalogue's `form.error.<code in lower case, with hyphens>`; another code
  reads `form.error.invalid`. The library composes its messages from the failing keyword and the constraint and names
  no value (GDR-FORMS-2).

[#_the_pickers]
=== The Pickers

* *`CatalogPicker`* lists the entries of its catalog from `GET /api/v1/catalogs/{catalog}`. The list holds the retired
  entries too, marked `retired`, because a reference to a retired entry still resolves
  (xref:directory.adoc#AUN-DIR-4[AUN-DIR-4]). The picker offers the entries that are not retired; a held value that
  names a retired entry is shown with the name and the mark *retired* and can be kept or replaced, and a held value
  that names no entry of the list is shown as the reference itself with the mark *not found*. The server refuses an
  unresolvable reference on save with `REFERENCE_NOT_FOUND`.
* *`PersonPicker`* offers the persons from `GET /api/v1/directory/persons`, filtered by the typed text, and resolves
  a held pseudonym with `GET /api/v1/directory/persons/{pseudonym}`. A person entry that no login has bound yet
  (a prefilled entry, xref:directory.adoc#AUN-DIR-8[AUN-DIR-8]) is offered and shown with the mark *not yet bound*; it
  resolves like a bound one and may be referenced
  (https://github.com/cuioss/git-document-repository/blob/main/doc/specification/git-directory.adoc#GDR-DIR-7[GDR-DIR-7]).
  An erased person resolves to a former member
  (https://github.com/cuioss/git-document-repository/blob/main/doc/specification/git-directory.adoc#GDR-DIR-4[GDR-DIR-4]):
  the field shows the mark *former* with the team and the role the entry held, never a name, and the picker does
  not offer such a person. A pseudonym that does not resolve is shown as *unknown person*.
* *`DocumentRefField`* is a text field for the reference. It resolves what it holds with
  `GET /api/v1/references/resolve` and shows the title of the target and, when the target has a canonical address
  (<<AUN-WEB-3>>), a link to it, or the mark *not found*. A reference into a repository the user may not read is
  reported as not found (xref:data-protection.adoc#AUN-DP-2[AUN-DP-2]).

[#_asciidoc_preview]
=== AsciiDoc Preview

An `AsciiDocField` is a text area for the source and a preview that the server renders: the form sends the source to
`POST /api/v1/render/asciidoc` no sooner than 500 ms after the last change and drops the answer of a request that a
later one has overtaken. The server renders in the strictest safe mode of Asciidoctor, `secure`, in which the
document can read no file, include nothing and fetch nothing from a URI
(link:https://docs.asciidoctor.org/asciidoctor/latest/safe-modes/[Asciidoctor, Safe Modes]), and sanitises the HTML
against an allow-list (<<AUN-WEB-8>>). The answer is HTML, and the web app puts no `{@html}` in a view: it parses the
answer with `DOMParser`, which runs no script, and builds its own elements from the nodes that its copy of the
allow-list names, dropping every other node and attribute. The allow-list of the server and of the web app is the same:

[cols="1,3"]
|===
|Elements |Attributes

|`p`, `br`, `hr`, `div`, `span`, `strong`, `b`, `em`, `i`, `code`, `pre`, `sub`, `sup`, `blockquote`, `ul`, `ol`, `li`,
`dl`, `dt`, `dd`, `h2` to `h6`, `table`, `caption`, `thead`, `tbody`, `tfoot`, `tr`, `th`, `td`
|None, except `colspan`, `rowspan` and `scope` on `th` and `td`, and `start` on `ol`

|`a`
|`href` with the scheme `https`, `http` or `mailto` only, or a fragment of the same document; `rel` is
`noopener noreferrer`, and no `target`
|===

No `img`, `script`, `style`, `iframe`, `form`, `class`, `id`, `style` or event handler survives, and the page's policy
allows no image from another origin anyway (<<AUN-WEB-8>>). A source that is too large or an unavailable renderer
costs the preview only: the field notes that no preview is shown and the user goes on editing; the source is saved
as written.

[#_read_only_rendering]
=== Read-Only Rendering

The same `SchemaForm` renders a document that is read, a revision and a document as of a date, with `readOnly` set:
every component shows its value as text and not as a control. A `DateTimeField` shows the localised date and time; a
`Select` the text of the option; a `Toggle` yes or no (a boolean that is absent is an empty value and shows the dash);
a `CatalogPicker`, a `PersonPicker` and a `DocumentRefField` the
name, the person or the title with their marks and the link; a `DataTable` the table without the row editor; an
`AsciiDocField` the rendered source (the same request), and the source as preformatted text, with a note that it is not
rendered, when the renderer is unavailable or the source exceeds the preview limit, so that what is read is never
lost; an empty value a dash. The marks *retired*, *not yet bound*,
*former* and *not found* are part of the reading, not of the editing. The same labels, sections and hints apply, so
that what is read has the shape of what was edited.

[#AUN-WEB-5]
== AUN-WEB-5: Drafts, Saving and Conflicts

* A form must save a draft no later than 5 seconds after the last change.
* A conflict must be shown with the fields that differ, each with the own and the other value; the draft must be kept.
* A save by another user to an open document must be visible within 5 seconds through the event stream.

Requests:

* Draft save: debounced, at most 5 s after the last change, `PUT /api/v1/drafts/{repository}/{id}`.
* Save: `POST /api/v1/documents/{repository}/{id}/save` with the blob ids loaded; the outcomes are those of the save
  in xref:architecture-and-modules.adoc#operation-outcomes[Architecture and Modules, Operation Outcomes]. On
  `GIT_UNAVAILABLE` the draft is kept, and the user saves again later.
* Event stream: `GET /api/v1/events` (`text/event-stream`); event `document-saved` with repository, id, fields; the
  open form refreshes the fields not edited locally. The events `document-created`, `document-transitioned` and
  `release-requested` are PROVISIONAL (xref:rest-api.adoc#_lifecycle_events[REST API Register, Events of the Lifecycle]).

[#AUN-WEB-6]
== AUN-WEB-6: Review and Release

* Release must show the diff of the structured data against the last released state.
* Every control whose transition requires step-up, under the shipped workflows the release control, must start it when
  needed and say so beside the control, in domain words and whatever the method: "You confirm your identity once
  more before the release." The control itself names the domain act only ("Release"); a mechanism such as MFA,
  step-up or password is never a label.

Requests:

* Diff: `GET /api/v1/documents/{repository}/{id}/diff?from=released` returns a structured diff of the YAML data; the
  view groups it by schema section.
* Release: `POST /api/v1/releases/{repository}/{id}`; the outcomes are those of the release in
  xref:architecture-and-modules.adoc#operation-outcomes[Architecture and Modules, Operation Outcomes];
  `STEP_UP_REQUIRED` carries the step-up address (xref:authentication.adoc#AUN-AUTH-4[Authentication, AUN-AUTH-4]).
  The button reads "Release" in every case; when the release requires step-up, the margin says that the user confirms
  their identity once more. With local users the password is asked in a dialog titled "Confirm your identity" and sent
  as `{"password"}` with the release request (xref:authentication.adoc#AUN-AUTH-6[AUN-AUTH-6]).

[#AUN-WEB-7]
== AUN-WEB-7: Texts

* All user-facing text must come from the server's message catalogue in English and German.

`GET /api/v1/messages?lang=en|de` returns the catalogue as `application/json`: one object that maps every message key
(a string such as `samm.release.confirm`) to its text in the requested language; both languages hold the same keys. A
missing `lang` returns English; any other value is answered with `400`. `src/lib/i18n` caches the catalogue per
application version. A lint rule
fails on string literals in markup outside `src/lib/i18n`.

The catalogue has one source: `web-app/src/main/resources/META-INF/audit-notary/messages/messages_en.properties` and
`messages_de.properties` (UTF-8). The `web-app` JAR carries them; the application and the mock server (`web-mock`,
xref:testing.adoc#AUN-TEST-1[AUN-TEST-1]) serve them from the class path, and the web unit tests read the same
files.

[#AUN-WEB-8]
== AUN-WEB-8: Page Security

* The app must be served with a Content Security Policy that allows no `unsafe-inline` script.
* Every state-changing request must carry the anti-CSRF header; the server must refuse one without it. The one
  exception is the login of local users, `POST /j_security_check`, which has no session to take a token from: it must
  be refused unless its `Origin` header is present and is the application's own origin, checked before Quarkus handles
  the request (xref:authentication.adoc#AUN-AUTH-6[AUN-AUTH-6]).
* A state-changing request whose `Origin` header is present and is not the application's own origin must be refused.
* Generated AsciiDoc output must be rendered and sanitised by the server.

[cols="1,3"]
|===
|Header |Value

|`Content-Security-Policy`
|`default-src 'self'; script-src 'self' 'sha256-<bootstrap>'; style-src 'self'; img-src 'self' data:;
connect-src 'self'; frame-ancestors 'none'; base-uri 'none'; form-action 'self'`

|`X-Content-Type-Options`
|`nosniff`

|`Referrer-Policy`
|`no-referrer`
|===

Anti-CSRF: every non-`GET` request except the local login carries `X-CSRF-Token` with the value from `GET /api/v1/session`; the server
compares it with the session's token and answers a mismatch with `403`. Origin: a non-`GET` request with an `Origin`
header that differs from the application's own origin is answered with `403`; a request without `Origin` is decided
by the anti-CSRF header alone.

AsciiDoc: rendered by the server in safe mode; the HTML is sanitised against an allow-list before it is returned.

[#AUN-WEB-9]
== AUN-WEB-9: Shell Requests

* The shell must start from three requests: the application status, the message catalogue and the session.
* Every refused `/api/v1` request must answer a JSON body that names its outcome, so the web app decides by the outcome
  and never by the status code alone.

[cols="2,1,3"]
|===
|Request |Login |Answer

|`GET /api/v1/status`
|no
|`{"version", "degraded", "loginProvider", "repositories": [{"alias", "fetch"}]}`; `degraded` is `true` while a fetch
of a repository fails (xref:architecture-and-modules.adoc#AUN-GEN-6[AUN-GEN-6]), `fetch` is `UP` or `DOWN`;
`loginProvider` is `oidc` or `local`, and with `local` the shell shows the notice of
xref:authentication.adoc#AUN-AUTH-6[AUN-AUTH-6] on every page. Carries no personal data.

|`GET /api/v1/messages?lang=en\|de`
|no
|The catalogue (<<AUN-WEB-7>>)

|`GET /api/v1/session`
|yes
|`{"user": {"pseudonym", "name"}, "rights": [{"repository", "actions"}], "csrfToken", "firstLoginRequired"}`;
`firstLoginRequired` is `true` until the own directory entry is saved
(xref:directory.adoc#AUN-DIR-2[AUN-DIR-2]), `pseudonym` is then `null`

|`GET /api/v1/due`
|yes
|`{"items": [{"kind", "lens", "title", "address", "due"}]}`: the launcher of the *Due* lens; `kind` is `deadline`,
`review` or `release`, `address` a canonical address (<<AUN-WEB-3>>), `due` an ISO 8601 date. The item of a pending
release request of an agent has four members more, `requestId`, `requestedBy`, `requestedAt` and `comment` (PROVISIONAL,
xref:rest-api.adoc#_release_requests[REST API Register, Release Requests])

|`GET /api/v1/events`
|yes
|The event stream (<<AUN-WEB-5>>); besides `document-saved` the event `status` with the body of
`GET /api/v1/status`
|===

Refusals:

[cols="1,1,3"]
|===
|Status |`outcome` |Meaning

|`401`
|`UNAUTHENTICATED`
|No session; the body carries `login`, the login address (xref:authentication.adoc#AUN-AUTH-1[AUN-AUTH-1]); with local
users the web app's login page (xref:authentication.adoc#AUN-AUTH-6[AUN-AUTH-6])

|`401`
|`INVALID_CREDENTIALS`
|Local users: a release with a wrong step-up password; nothing is written
(xref:authentication.adoc#AUN-AUTH-6[AUN-AUTH-6]). A failed login is Quarkus' plain `401` of `/j_security_check`

|`403`
|`CSRF_REJECTED`
|Anti-CSRF header missing or wrong, or foreign `Origin` (<<AUN-WEB-8>>)

|`403`
|`FORBIDDEN`
|No mapped right (xref:authentication.adoc#AUN-AUTH-2[AUN-AUTH-2])

|`403`
|`FIRST_LOGIN_REQUIRED`
|Request outside the first-login allow-list (xref:directory.adoc#AUN-DIR-2[AUN-DIR-2])

|`422`
|`VALIDATION`
|`errors`: a list of `{"pointer", "code"}`, `pointer` a JSON Pointer into the request body

|`502`
|`IDENTITY_PROVIDER_UNAVAILABLE`
|`GET /api/v1/auth/login` cannot start the login: the provider's metadata cannot be read

|`503`
|`GIT_UNAVAILABLE`
|The Git server is unreachable (xref:architecture-and-modules.adoc#AUN-GEN-6[AUN-GEN-6])

|`503`
|`TOO_MANY_LOGINS`
|`GET /api/v1/auth/login` cannot start the login: 10,000 logins are pending (AUN-AUTH-1); with `Retry-After: 60`
|===

The login callback (xref:authentication.adoc#AUN-AUTH-1[AUN-AUTH-1]) answers a page that navigates with
`<meta http-equiv="refresh" content="0;url=<return>">`, so the page needs no script and passes the policy of
<<AUN-WEB-8>> unchanged. `POST /api/v1/auth/logout` answers `{"redirect"}`, the address the web app navigates to
(the provider's `end_session_endpoint`).
