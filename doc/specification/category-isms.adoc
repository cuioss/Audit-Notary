The ISMS category as configuration (`categories/isms/`): documents and the risk register. Reasoning:
xref:../concepts/category-isms.adoc[ISMS]. Repositories: `isms-core` (documents), `isms-register` (risk register).

[#AUN-ISMS-1]
== AUN-ISMS-1: Documents

* Policies, the scope, internal audit reports and management review reports must be schema-driven documents in
  `isms-core`, released with step-up (xref:authentication.adoc#AUN-AUTH-4[AUN-AUTH-4]).

[cols="1,2"]
|===
|Document type (kind) |Path in `isms-core`

|Policy (`policy`) |`policies/<ulid>/`
|Scope (`isms-scope`) |`scope/<ulid>/`
|Internal audit report (`audit-report`) |`audits/<ulid>/`
|Management review (`management-review`) |`management-reviews/<ulid>/`
|===

Each type is a per-document kind in the library's layout
(https://github.com/cuioss/git-document-repository/blob/main/doc/specification/git-forms.adoc#GDR-FORMS-3[GDR-FORMS-3]) with YAML data, AsciiDoc fragments and generated
output; the year of an audit or a review is a field, not a part of the path.

[#AUN-ISMS-2]
== AUN-ISMS-2: Risk Register

* Risks must be kept in a register with one file per entry.
* Every entry must receive a readable running number unique within the register, also when two users create entries
  concurrently; the number names the entry and is the target of references.

Path in `isms-register`: `risks/R-<n>.yaml`. The register is a numbered collection: its entries live on one
collection branch (`refs/heads/risks`), with no branch per entry. The readable number is assigned on the first save
by the library's running-number mechanism; it names the entry file, a release tag of the entry and the link target
(`isms-register:risk/R-042`).

[#AUN-ISMS-3]
== AUN-ISMS-3: Reporting Dates

* The application must show the risk register as of a given tag or date.

Register entries reach `main` only by release: the library's release of a numbered entry merges that entry's path
from the collection branch into `main` (path-level merge). The as-of view reads `main` and therefore shows released
entries only. `GET /api/v1/isms/risks?as-of=<tag|date>` is answered from an index the library builds for the given tag
or commit without changing the current index; a tag selects the tagged commit, a date the last commit on `main` at or
before the end of that day (UTC).

[#AUN-ISMS-4]
== AUN-ISMS-4: Operational Data by Reference

* Tasks and measures must be referenced by issue-tracker id; the application must not store task state in Git.

Measures and tasks are fields `issues: [<tracker-id>]`, entered by the user or the agent.

[#_open_questions]
== Open Questions

Decided provisionally with the Reports lens (UC-ISMS-3), recorded with the bodies in
xref:rest-api.adoc#_decided_reports[REST API Register, Open Questions]; the owner may change each one:

. *Reporting dates* (AUN-ISMS-3): `as-of` is a calendar date (UTC) or a tag name; the answer names the commit it read
  and lists the tags of the register; a date after today, a name that is no tag and a value of neither form are refused with
  `422` (`FUTURE`, `UNKNOWN_TAG`, `PATTERN`). The entries are summaries of the released entries as they were then.
. *The shape of an entry in the list* (AUN-ISMS-2): number, title, rating (`low` to `critical`), treatment (`mitigate`,
  `accept`, `transfer`, `avoid`), owning team, version, release time, review date and origin; the schema of a risk belongs to
  the ISMS lens.

Decided provisionally with the ISMS lens (UC-ISMS-1, UC-ISMS-2, UC-SAMM-6, UC-TM-3), recorded with the bodies in
xref:rest-api.adoc#_decided_isms[REST API Register, Open Questions]; the owner may change each one:

. *Documents* (AUN-ISMS-1): every type is released more than once, with one workflow for the category; each is one file with
  the part `data`; the fields are those of xref:rest-api.adoc#_isms_data[REST API Register, The Data Shape of an ISMS Document
  and of a Risk]; the generated output is not shown by the web app. Two versions are compared with the
  diff `from=<revision>&to=<revision>`.
. *Risks* (AUN-ISMS-2): the id of a risk is its running number `R-<n>`, assigned by the server at the first save, which needs
  only the title; the register as it is worked on is `GET /api/v1/isms/register`; a risk is released more than once, with the
  tags `risks/R-<n>/v<n>`.
. *Origin* (AUN-SAMM-6, AUN-TM-4): a risk made from a gap or a threat carries the reference as its read-only `origin`; the
  transfer is recorded in the threat model (`transferred`) when the risk is first saved.
. *Reviews* (AUN-ISMS-2): the review date is a field of the entry, not computed; the Due lens lists the reviews of released
  entries that are overdue or within 30 days.
