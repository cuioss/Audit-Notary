xref:../README.adoc[TrailHand documentation] » Specification

Two sources: `application.properties` for Quarkus runtime settings, and `trailhand.yaml` for the policy of the
application. Reasoning: xref:../concepts/application-architecture.adoc#_configuration[Application Architecture,
Configuration].

[#TRH-CONF-1]
== TRH-CONF-1: Configuration

* Policy configuration must be one YAML document validated against a bundled JSON Schema; `${NAME:-default}`
  placeholders must be resolved from the environment.
* An invalid configuration must stop the boot with one log record per violation.
* `--validate-config <dir>` must validate offline and exit with `0` for a valid and `1` for an invalid
  configuration.
* Secret values must not be representable in the YAML; the schema must accept only references (mounted file, KMS key
  id or Vault path).

=== application.properties

The application sets these values; the column shows the application's value, not the Quarkus default.

[cols="1,1,2"]
|===
|Key |Value |Meaning

|`quarkus.http.ssl-port`
|`8443`
|HTTPS listener

|`quarkus.http.insecure-requests`
|`redirect`
|Plain HTTP redirects to HTTPS

|`quarkus.management.enabled`, `quarkus.management.port`
|`true`, `9000`
|Health and metrics on their own port

|`quarkus.http.ssl.certificate.files`, `quarkus.http.ssl.certificate.key-files`
|`/run/secrets/tls/tls.crt`, `/run/secrets/tls/tls.key`
|TLS certificate chain and private key (PEM), mounted as a secret

|`trailhand.config.dir`
|`config`
|Directory holding `trailhand.yaml`

|`trailhand.oidc.jwks-url`
|not set
|The address of the provider's keys, set only when the application reaches the provider under another origin than
its issuer (split horizon, as in the compose stack); otherwise the keys are found through the issuer's well-known
document
|===

Token Sheriff reads its own keys (`sheriff.client.*`, `sheriff.token.issuers.*`); the application derives them from
`trailhand.yaml` → `oidc` and `web.origin` with an ordinal above `application.properties` and below the environment.
Settings of the deployment's network stay in the environment, among them `SHERIFF_CLIENT_BACK_CHANNEL_ORIGIN` (the
origin the client dials instead of the issuer's), `SHERIFF_CLIENT_ALLOWED_EGRESS_HOSTS` and
`SHERIFF_TOKEN_ISSUERS_TRAILHAND_JWKS_HTTP_ALLOWED_EGRESS_HOSTS` (hosts on private addresses that the egress guard
admits).

=== trailhand.yaml

Validated against `schema/trailhand.schema.json` (bundled). Top-level keys:

[cols="1,1,3"]
|===
|Key |Required |Content

|`repositories`
|yes
|List of repositories (<<TRH-CONF-2>>)

|`rights`
|yes
|Map of identity-provider group → list of `{repository, actions}`; actions from `read`, `edit`, `approve`,
`administer-catalogs`

|`oidc`
|yes
|Web login through Token Sheriff: `issuer`, `client-id`, `client-credential-ref` (client secret, or the private key
for `private_key_jwt`), `groups-claim` (default `groups`)

|`categories`
|yes
|List of the enabled categories (`samm`, `threat-models`, `incident-reports`, `isms`); their behaviour comes from
their definitions in the `categories` module and the named extension points
(xref:architecture-and-modules.adoc#TRH-GEN-1[TRH-GEN-1])

|`step-up`
|yes
|`acr` (list of `acr` values that state multi-factor authentication), `amr` (list of `amr` values accepted instead,
default `mfa`, the value for multiple-factor authentication; a single method such as `otp`, one-time password, is not
multi-factor; values as registered in link:https://www.rfc-editor.org/rfc/rfc8176#section-2[RFC 8176, §2]),
`max-age` (default `PT5M`) (xref:authentication.adoc#TRH-AUTH-4[Authentication, TRH-AUTH-4])

|`signing`
|yes
|`key-ref` (commit-signing key; SSH format), `allowed-signers` (path of a mounted file in Git's `allowed_signers`
format with the public commit-signing keys and their validity periods; never read from a repository,
https://github.com/cuioss/git-document-repository/blob/main/doc/specification/git-store.adoc#GDR-STORE-14[GDR-STORE-14])

|`save`
|yes
|`max-attempts`: the number of attempts of a save, or of a push of notes, when the lease is refused or the push is
rejected (https://github.com/cuioss/git-document-repository/blob/main/doc/specification/git-store.adoc#GDR-STORE-3[GDR-STORE-3])

|`drafts`
|yes
|`expiry`: ISO 8601 period after which a draft not changed is deleted
(https://github.com/cuioss/git-document-repository/blob/main/doc/specification/git-store.adoc#GDR-STORE-7[GDR-STORE-7])

|`fetch`
|no
|`interval`: ISO 8601 duration of the periodic fetch, one value for all repositories, default `PT5M`
(<<TRH-CONF-2>>)

|`anchor`
|yes
|Anchoring of releases and checkpoints
(https://github.com/cuioss/git-document-repository/blob/main/doc/concepts/evidence-and-companion-stores.adoc#_the_anchor[Evidence and Companion Stores, The Anchor]):
`provider` (`signed`, the default, `rfc3161`, or `none`, which switches anchoring off), `checkpoint-interval`
(ISO 8601 duration, default `P1D`), `signed-key-ref` (the anchor key of the own timestamp; required with the provider
`signed`; must differ from `signing.key-ref`),
`signed-allowed-signers` (path of a mounted file in the `allowed_signers` format with the public anchor keys and their
validity periods; required with the provider `signed`; must hold no commit-signing key; never read from a repository,
https://github.com/cuioss/git-document-repository/blob/main/doc/specification/git-store.adoc#GDR-STORE-18[GDR-STORE-18]), `timestamp` (`url`, `trust`, `credentials-ref`;
`url` and `trust` required with the provider `rfc3161`, the library's `timestamp.url`, `timestamp.trust` and
`timestamp.credentials` of https://github.com/cuioss/git-document-repository/blob/main/doc/specification/git-timestamp.adoc#GDR-TSA-1[GDR-TSA-1])

|`mcp`
|yes
|`canonical-uri`, `authorization-servers`, `allowed-origins`

|`web`
|yes
|`origin` (the application's own origin, an absolute `https` URI without path: the `Origin` check of
xref:web-app.adoc#TRH-WEB-8[TRH-WEB-8] compares with it, and the login callback is `<origin>/api/v1/auth/callback`),
`session.idle-timeout` (default `PT30M`), `session.max-lifetime` (default `PT8H`), `information-text-ref`

|`directory`
|no
|The person directory (xref:directory.adoc#TRH-DIR-1[Directory, TRH-DIR-1]): `persons.provider` (default `git`),
`persons.repository` (default `directory`), `confirmation-interval` (default `P12M`), `backstage` (the import of
xref:directory.adoc#TRH-DIR-6[TRH-DIR-6])
|===

The library settings of https://github.com/cuioss/git-document-repository/blob/main/doc/specification/git-store.adoc#store-configuration[`git-store`, Configuration] come
from these keys: `repositories`, `save.max-attempts`, `drafts.expiry`, `fetch.interval`, `signing.allowed-signers`,
`anchor.provider`, `anchor.checkpoint-interval` and `directory.persons.provider` under the same names; the library's
`signing.key-source` and `signing.key` from `signing.key-ref`, its `anchor.signed.key-source` and
`anchor.signed.key` from `anchor.signed-key-ref`, its `anchor.signed.allowed-signers` from
`anchor.signed-allowed-signers`. The `step-up` keys are those of
https://github.com/cuioss/git-document-repository/blob/main/doc/specification/git-forms.adoc#GDR-FORMS-7[`git-forms`, GDR-FORMS-7]. Where the application's default
differs from the library's (`anchor.provider`, `fetch.interval`, `directory.confirmation-interval`), the
application's applies; the library keys not listed here (`anchor.releases`, `anchor.retry-interval`,
`anchor.signed.max-clock-skew`) are not configurable and keep their library defaults.

Every key ending in `-ref` accepts one of three reference forms; no key accepts a secret value:

* `file:/run/secrets/...`: a mounted file.
* `kms:<key-id>`: a key held by the KMS and used there; accepted only by the signing keys (`signing.key-ref`,
  `anchor.signed-key-ref`).
* `vault:<path>`: a secret of Vault's key-value engine; accepted by every key except the signing keys.

Placeholders: `${NAME}` and `${NAME:-default}` in any string value, resolved from the environment before validation.
`NAME` is an environment variable name (letters, digits and underscores, not starting with a digit). An unresolved
placeholder without default is a boot error, and so is any other `${...}`, so it never passes as a literal value.

=== Boot Validation

Before the application accepts requests, every rule runs; each violation produces one `ERROR` record, and any
violation stops the boot. Besides the schema, the rules refuse what the schema cannot see: two repositories with one
alias, a `rights` entry or `directory.persons.repository` naming an unknown alias, a `-ref` value in a form its key
does not accept, an `anchor.signed-key-ref` equal to `signing.key-ref`, an `mcp.canonical-uri` that is not an
absolute HTTPS URI without fragment, and a `web.origin` that is no HTTPS origin or a `web.session.idle-timeout` longer
than `web.session.max-lifetime`. `--validate-config <dir>` runs the same rules offline.

The bootstrap enforces the rules of the keys it reads: `repositories`, `rights`, `oidc`, `web` and `fetch`, the
placeholders, and `web.origin` and the session lifetimes. Until the Vault adapter is built, `file:` is the only
reference form it accepts for the references it reads, `repositories[].credential-ref` and
`oidc.client-credential-ref`; `vault:` and `kms:` are refused there at boot. Other `-ref` keys, such as
`web.information-text-ref`, are not read yet and not checked. The JSON Schema and the rules of `signing`,
`anchor`, `mcp` and `directory`, with the per-key reference forms, apply once their modules are built; until then a
value under those keys is not checked.

[#TRH-CONF-2]
== TRH-CONF-2: Repositories and Refresh

* Every repository must have a remote; a single-server setup uses a local bare repository as its remote.
* Every repository must declare its confidentiality class and its retention period, and nothing else may declare a
  retention period.
* The application must refresh every repository by a periodic fetch, at one interval for all repositories
  (`fetch.interval`, default `PT5M`), and after its own saves.

[cols="1,1,3"]
|===
|Field |Required |Meaning

|`alias`
|yes
|Stable alias used in references (`isms-register`); `isms-incidents-<year>` names one repository per year

|`remote`
|yes
|URL of the remote: HTTPS, or `file:` for a local bare repository

|`confidentiality`
|yes
|`public-internal`, `restricted`, `strongly-restricted`

|`retention`
|yes
|`unlimited` or an ISO 8601 period, counted from the repository's creation (for `isms-incidents-<year>` from the end
of that year)

|`credential-ref`
|for HTTPS
|Reference to the credential of the technical user, the only Git credential
|===
