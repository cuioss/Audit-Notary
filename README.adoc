== What is it?

*TrailHand* -- the CISO's friend -- is the server application in which a development organisation maintains its
OWASP SAMM assessments, threat models, incident response reports and ISMS documents as versioned documents, on the Git
server it already runs. No client holds a clone and no additional database is needed.

It is built on the libraries of https://github.com/cuioss/git-document-repository[`git-document-repository`] and on
https://github.com/cuioss/TokenSheriff[Token Sheriff], runs as a Quarkus native application on Java 25, and has two
interfaces: a web app for people and an MCP server for AI agents acting for a user.

The documentation starts at link:doc/README.adoc[doc/README.adoc]: concepts, architecture decisions and
specification. New readers start with the link:doc/concepts/trailhand-overview.adoc[Overview].

== Build

The target is Java 25; CI builds on Java 25 and 27.

[source,bash]
----
./mvnw clean verify
----

The root `de.cuioss:trailhand-parent` is a parent POM without modules so far; the modules of
link:doc/specification/architecture-and-modules.adoc[Architecture and Modules] are added as they are built.

== Credentials

All secrets (GPG, Sonatype, Sonar, Release App) are managed at the https://github.com/cuioss/cuioss-organization[cuioss organization level]. The caller workflows pass them explicitly to the reusable workflows; pass only the secrets a reusable workflow declares, an undeclared one makes every run end in `startup_failure`. No repo-level secrets need to be configured.

== Releasing

Merging a change of `release.current-version` in `.github/project.yml` *is* a release: the central
guard in `reusable-maven-release.yml` publishes to Maven Central whenever that value differs from the
merge commit's first parent and no tag for it exists. Maven Central releases cannot be withdrawn.
Every other `project.yml` edit reaches the release workflow too and is refused by the guard.

* `current-version: 0.1.0` is declared together with `0.1.0-SNAPSHOT` in the POM. Do not touch it in an ordinary PR.
  The first release is a deliberate `workflow_dispatch` from `main`, and only once there is something to release.
* Every later release goes through the runbook `.claude/skills/release/SKILL.md`: a dedicated
  `chore/release_<version>` PR that changes nothing but the version, merged only after the pre-cut
  checks.
* Do not rewrite the `cuioss/cui-java-module-template` literal in `.github/workflows/release.yml`; it only excludes the template repository itself.
* `maven-build.enable-snapshot-deploy` is `true`: every push to `main` deploys the `0.1.0-SNAPSHOT` modules to the Sonatype snapshot repository. This is not a release.
